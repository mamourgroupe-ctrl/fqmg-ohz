- **D-017 (المرحلة 3):** مصادقة جلسات داخلية بالكود (`src/auth/session.ts`: HMAC-SHA256
  على كوكي موقّع، `FQMG_USERS` بالبيئة، `npm run auth:hash`) بدل الافتراضي المعلّق
  Auth.js/next-auth@beta. الأسباب: next-auth@beta (v5) غير مستقر ويتطلب اعتمادات
  موفّر OAuth غير متاحة للتحقق هنا، بينما معايير المرحلة (401 موحّد، فشل مغلق، إبطال
  فوري، بلا اعتماديات جديدة) تتحقق باعتماديات صفرية والتبديل لاحقًا معزول خلف
  `requireUser()`. المطلوب: مراجعة المالك (المرحلة 3 = ⚠️ بشرية) قبل الدمج.
- **D-018:** `AUTH_ENABLED` الافتراضي **مفعّل** (لا قيمة = فرض). `AUTH_ENABLED=0` مخرج
  تطوير واحد يلغي المصادقة والتفويض وحد المعدل معًا (يُحذَّر عند التفعيل) — يمنع أنماط
  «بدون مصادقة لكن بحدود» التي تُترك بالخطأ في الإنتاج.
- **D-019:** سياسات حد المعدل الابتدائية (src/auth/rate-limit.ts): generate 10/د،
  plan 30/د، voice-synthesize 10/د، voice-providers 30/د، voice-audio 60/د، agent-qa
  5/5د، lambda-render 5/د، lambda-progress 60/د، auth-login 5/5د لكل IP، ip-global
  120/د لكل IP. المخزن ذاكرة process-local وراء واجهة `RateLimitStore` — المرحلة 5
  تستبدلها بـ Redis دون تغيير المواقع.
- **D-020:** الملكية: `owner` يُخزَّن مع كل مهمة وكائن ميزانية عند الإنشاء من الجلسة؛
  GET/DELETE/preview للوظائف يرفض غير المالك بـ 403 (والمعاينة تتحقق قبل كشف وجود
  المهمة)؛ مراجع الصوت بلا مالك مسجّل ترفض 403 (fail-closed). ميزانية كل مستخدم:
  `AGENT_USER_DAILY_BUDGET_USD` (افتراضي = السقف اليومي العام) مع حجز/تسوية/استرداد
  لكل مهمة كما هو.
