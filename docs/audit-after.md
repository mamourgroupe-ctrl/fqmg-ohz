## لماذا هذه الطريقة لكل finding

1. **zod + 12 نتيجة `@remotion/*` مترتبة:** المسار الأول (ترقية Remotion كاملًا) مستنفد بالدليل —
   أحدث إصدار على `latest` (`4.0.539`) ما زال يثبّت `zod: "4.5.4"` بدقة عبر
   `@remotion/studio-protocol`. المسار الثاني المعتمد: `overrides.zod = ^4.6.7` مع إثبات توافق
   (كل البوابات + الحزمة الفعلية أدناه).
2. **سلسلة ai-sdk (5 low ثم 2 high + 4 moderate أثناء العمل):** الترقية إلى «الأحدث»
   (`ai ^5.0.282`, `@ai-sdk/react ^2.0.285`, `@ai-sdk/openai ^2.0.136`, provider-utils 3.0.42)
   أدخلت الشجرة في نطاقات ثغورة **نُشرت أثناء تنفيذ المرحلة نفسها**: undici 5.29.0 +
   @fastify/busboy 2.1.1 (عاليان)، ونطاقات moderate على ai/react/gateway/provider-utils.
   الحل: تثبيت دقيق داخل «نوافذ الأمان» الحالية (جدول أعلاه) — كلها إصدارات غير ثغورة
   بتاريخ اليوم، وprovider-utils 3.0.30 يزيل undici/busboy نهائيًا.
3. **dompurify (صارت critical أثناء العمل):** monaco 0.57.0 يثبّت `dompurify: "3.4.15"` بدقة
   وهو ≤3.4.16 الثغور. الحل: `overrides.dompurify = 3.4.17` (أول إصدار خارج كل النطاقات الثغورة).
4. **monaco-editor:** 0.57.0 دخلت في نطاق low جديد (`>=0.57.0-rc.2`) بلا إصلاح منشور؛
   0.56.0 المستقرة نظيفة من كل النطاقات الحالية، و`@monaco-editor/react@4.7.0` يعلن peer
   `>= 0.25.0 < 1` فمتوافق. تُركت 0.56.0 مع اختبار سياسة يمنع الانتقال غير الواعي.
5. **fast-uri:** رفع داخل النطاق عبر `npm audit fix` (غير كاسر) + ترقية google-auth-library minor.

## انزياح قاعدة التنبيهات أثناء المرحلة (موثّق للشفافية)

بين التقاط «قبل» وتطبيق الإصلاح، نشرت GitHub قاعدة تنبيهات جديدة غيّرت النطاقات:
dompurify أصبحت critical، وmonaco 0.57.0 أصبحت low، وسلسلة ai-sdk أضافت high/moderate جديدة.
لذلك لم يكفِ تنفيذ اقتراحات npm لحظة القياس الأول؛ أعيد تقييم النطاقات من السجل مباشرة
(`npm info …` لكل حزمة) ووُضّعت النسخ النهائية فوق النطاقات السارية وقت الإغلاق. أي ترقية قادمة
عبر Dependabot يجب أن تُراجع بنفس الطريقة (تنبيه مكتوب في `.github/dependabot.yml`).

## ما لم يُتحقق منه ولماذا (بند 9 من CLAUDE.md)

- **عرض متصفح حقيقي (remotion render) داخل بيئة العمل:** تعذّر لثلاثة أسباب مثبتة:
  لا يوجد أي متصفح في النظام (`which chromium chromium-browser google-chrome` فارغ)،
  وتنزيل Headless Shell من remotion.media محجوب بسياسة شبكة البيئة
  (`npx remotion browser ensure` يفشل)، وتشغيل workflow يدوي مرفوض للرمز
  (`gh workflow run render-smoke.yml` ← HTTP 403 Resource not accessible by integration).
  **إجراء المالك المطلوب:** من واجهة GitHub ← Actions ← «Render smoke test (manual)» ←
  Run workflow ← `code_ref = arena/cc0b132c-fqmg-ohz`. يشغّل عرض 2 ثانية + بوابة ffprobe
  على runners كاملة الشبكة (يختبر أيضًا zod 4.6.7 داخل حزمة العرض الفعلية).
- محتوى تقرير audit على GitHub runners: البوابة الإلزامية الآن ستُظهره في CI على هذا الـ PR.
