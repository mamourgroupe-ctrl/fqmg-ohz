# تقييم دمج ArtCraft في مشروع fqmg-ohz

- **تاريخ الفحص:** 2026-10-12
- **المصدر المفحوص:** <https://github.com/storytold/artcraft> (`main`, مُحدَّث 2026-10-11)
- **النتيجة:** **لا يمكن دمج الكود** في هذا المشروع. يمكن دمج **القابليات** عبر واجهة Omni API المستضافة، إن أردت ذلك.
- **حالة التنفيذ:** تقييم فقط — لم يُضَف كود ولم يُعدَّل أي شيء بناءً على هذا التقرير.

## 1. ما هو ArtCraft فعليًا (معطيات مفحوصة)

| البند | القيمة |
| --- | --- |
| النوع | تطبيق سطح مكتب (IDE) للصور والفيديو بالذكاء الاصطناعي، Rust + Tauri مع واجهة Nx/React/Vite |
| اللغات | Rust ~9,967,836 سطرًا، TypeScript ~6,598,295، JavaScript ~112,658، Python ~43,009 |
| حجم المستودع | 1,374,746 KB (~1.37 GB) |
| الترخيص | Apache-2.0 / MIT (ملفان: `LICENSE-APACHE`, `LICENSE-MIT` مع `NOTICE`) |
| بنية المجلدات | `crates/` (api_clients, desktop, lib, schema, testing, vendor), `frontend/` (Nx), `artcraft-native/`, `_database/` (SQLite migrations), `.sqlx/`, `script/` |
| الباكند | **ليس في هذا المستودع** — حسب `_docs/dev_setup.md`: «Backend services and website builds live in the separate `artcraft-services` repository.» |

**متطلبات البناء** (من `_docs/dev_setup.md`): Rust + npm/nvm (Node 24) + Tauri CLI 2.10، ثم `./script/artcraft/unix_dev.sh` الذي يشغّل Vite على `127.0.0.1:5193` وTauri معًا. أي أنه يحتاج بيئة سطح مكتب (WebView/GPU) — لا يوجد وضع خادم HTTP قابل للاستضافة.

## 2. لماذا لا يصلح الدمج المباشر

1. **لا يوجد مكوّن قابل للتضمين**: لا حزمة npm، ولا مكتبة Rust قابلة للاستدعاء من Next.js، ولا وضع server داخل المستودع العام. الاتصال الداخلي بين الواجهة والـRust يمر عبر Tauri IPC الأصلي لا عبر HTTP.
2. **تعارض في طبقة التشغيل**: التطبيق GUI مع WebView وSQLite محلية، ومشروعنا Next.js/Remotion يعمل كخدمة ويب. لا سطح مشترك غير ملفات التوثيق.
3. **غير قابل للبناء أو التشغيل هنا**: هذا الصندوق بلا `cargo`/`rustc`، بلا GPU، بنواتين و3 GB RAM و18 GB قرص. كما أن نسخ المستودع (1.37 GB) يتجاوز بكثير سقف المخرجات المعتمد (~128 MB) وسيتضخم تاريخ Git دون أي فائدة تشغيلية.
4. **الترخيص ليس العقبة**: Apache-2.0/MIT متوافق مع ترخيص هذا المشروع (MIT)، لكن أي نسخ فعلي لكودهم يستلزم الإبقاء على `NOTICE` وإشعارات الملفات وبيان التعديلات — وهذا لا معنى له في مشروع TypeScript لا يشغّل Rust.

## 3. ما يمكن دمجه فعلًا: ArtCraft Omni API كمزوّد توليد وسائط

حسب وثائقهم العامة (`_docs/artcraft_omni_api.md` و<https://storyteller-docs.netlify.app/>):

| البند | القيمة |
| --- | --- |
| القاعدة | `https://api.storyteller.ai` (والتطوير على `http://localhost:12345`) |
| المفتاح | يبدأ بـ `artcraft_api_` بطول 53 حرفًا |
| المصادقة | ترويسة `Authorization: Bearer artcraft_api_…` (تُرفض الكوكيز عمدًا) |
| مثال مسار | `POST /v1/omni_api/generate/video` (يقبل روابط صورة/فيديو/صوت مرجعية) |
| كتالوج النماذج | 62 نموذجًا: صور (16)، فيديو (25)، موسيقى وصوت (5)، مجسمات 3D (11)، عوالم/Gaussian splats (5) |

> **تحذير إثبات:** هذا الوصف مأخوذ من توثيقهم المنشور فقط. لم يُختبر أي نداء حقيقي: هذا الصندوق لا يستطيع الوصول إلى `api.storyteller.ai` (فُحص: لا اتصال)، والوصول إلى الـAPI مُقيَّد لكل حساب («API access is gated per account»).

### شكل الدمج المقترح (إن وافقت)

ملاءمة المعمارية عالية: محرك الصوت الموجود (`src/voice`) هو نفس النمط المطلوب حرفيًا — contracts + adapters + routing + cache + managed references + fail-closed.

```
src/media/
├── contracts/media-contract.ts      # مخططات Zod: طلب توليد، أصل ناتج، مرجع مُدار
├── providers/artcraft-omni.ts       # مُهايئ: مصادقة، صور/فيديو/صوت/3D، مهلة وإعادة محاولة
├── cache/managed-media-cache.ts     # تخزين محلي content-addressed + مراجع UUID مبهمة
├── project/apply-media-to-motion-specification.ts   # إرفاق الأصل بالمواصفة كـ asset/مشهد
└── api/request-schema.ts
src/app/api/media/{generate,asset/[id],providers}/route.ts
```

- مفاتيح البيئة: `ARTCRAFT_OMNI_API_KEY`, `ARTCRAFT_OMNI_BASE_URL`, `MEDIA_CACHE_DIR`, حدود المهلة/الحجم.
- مسار فحص يدوي `npm run media:live-check[:plan]` بنفس نمط `voice:live-check` (يطبع الطلبات بلا شبكة أولًا).
- اختبارات fixtures فقط، وحالة كل موفّر تظهر «غير مهيّأ» ما لم يوجد مفتاح فعلي — بنفس صرامة محرك الصوت الحالية.
- إخفاء الأخطاء، عدم كشف المفاتيح أو المسارات المحلية، ورفض مصادر الأصول غير المسموح بها.

### مخاطر وحدود يجب تسجيلها عند التنفيذ

1. مفتاح API مقيّد بالحساب وقد يتطلب تفعيلًا من فريق ArtCraft.
2. شروط استخدام المزوّد وحقوق المخرجات واستخدامها التجاري مسؤوليتك — يلزم التحقق منها قبل الإنتاج.
3. تكاليف حقيقية لكل نداء توليد؛ لا يجوز تشغيل الفحص الحيّ تلقائيًا.
4. لا مصادقة ولا rate limiting في تطبيقنا بعد؛ حد النشر الموثّق في `docs/voice-api.md` ينطبق كما هو.
5. التوثيق الخارجي قابل للتغيير؛ لذلك المُهايئ يجب أن يفشل مغلقًا عند تغيّر العقد.
