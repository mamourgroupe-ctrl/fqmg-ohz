# تدقيق بنية المستودع الأصلي

**تاريخ التدقيق:** 2026-10-08 (UTC)
**الفرع المفحوص:** `arena/ede0565d-fqmg-ohz`
**النتيجة قبل التعديل:** شجرة Git نظيفة؛ لا تغييرات مستخدم غير محفوظة.
**طريقة العزل:** أُنشئت النسخة الجديدة في `fqmg-ohz-next/` فقط. لم تُنسخ الشيفرة الأصلية إلى النسخة الجديدة.

## ملخص البنية

المستودع الأصلي تطبيق Next.js App Router وReact/TypeScript، مع Remotion 4. مجلد `src/app/` يحوي صفحات التطبيق وواجهات API، و`src/components/` واجهة المحادثة/المحرر/المعاينة، و`src/hooks/` حالة المحادثة والتوليد والتصحيح، و`src/remotion/` تركيب Remotion ومترجم الشيفرة، و`src/lambda/` تكامل العرض السحابي. توجد أمثلة وملفات إرشاد Remotion في `src/examples/` و`src/skills/` و`.agents/`.

### الاعتماديات والإعداد

- `package.json` الأصلي مستقل عن هذا المجلد: Next.js `16.3.6`، React `19.2.1`، Remotion `4.0.534`، TypeScript `5.9.3`، Zod `4.5.4`، وحزم AI SDK وOpenAI وRemotion Lambda وغيرها.
- ملف القفل الأصلي هو `package-lock.json` في الجذر. لم يُعدّل ولم يُستخدم لتثبيت النسخة الجديدة.
- إعدادات Next.js في `next.config.js`؛ وإعداد Remotion في `remotion.config.ts` و`src/remotion/webpack-override.mjs`.
- TypeScript صارم مع alias `@/*`، لكن إعداد `paths.react` يشير إلى مسار خارج المشروع، ما يقلل قابلية النقل المستقلة.
- `.env.example` الأصلي يذكر مفاتيح Remotion AWS وOpenAI فقط. لم تُقرأ أو تُنسخ أي قيمة سرية فعلية.
- لم يكن `node_modules/` موجودًا وقت التدقيق. يتطلب فحص بناء الأصل تثبيتًا مستقلاً لم يُنفذ حتى لا تتغير بيئة الأصل أو ملفاته.

### توليد الذكاء الاصطناعي والمترجم

- `src/app/api/generate/route.ts` يستخدم AI SDK مع `@ai-sdk/openai`، ويطلب مخرجات React/Remotion، ثم يعالج أو يطبق تعديلات نصية على الشيفرة.
- المهارات تُختار من `src/skills/` وتُضمّن في تعليمات التوليد.
- `src/remotion/compiler.ts` يحوّل النص بواسطة Babel ثم ينشئ مكوّنًا عبر `new Function`؛ وتوجد في `src/remotion/DynamicComp.tsx` معاينة لذلك المكوّن.
- هذا النمط يعني تنفيذ شيفرة مولّدة، ولذلك لا يجوز إعادة استخدامه في النسخة الجديدة دون عزل أمني ومراجعة تهديدات. Phase 1 الجديدة تعتمد بيانات Motion Specification فقط ولا تنفذ شيفرة من المستخدم.

### العرض والمقاسات والاختبارات

- `src/remotion/Root.tsx` يعرّف تركيبًا واحدًا `DynamicComp` بدقة ثابتة `1920×1080` و30 FPS؛ لا يوجد سجل مركزي للمقاسات المطلوبة `9:16` و`1:1` و`4:5` و`16:9`.
- العرض السحابي يمر عبر مسارات Lambda في `src/app/api/lambda/` وواجهة `src/lambda/api.ts`، مع polling من hook. لا توجد طبقة مواصفة حركة مستقلة عن محرك العرض.
- الأنواع الحالية (`types/constants.ts`, `types/schema.ts`) تصف شيفرة ودقة/مدة تركيب أساسيين، لا مشاهد وأصول وصوت وترجمة وعلامة تجارية.
- لم يُعثر على ملفات اختبارات أو إعداد Vitest/Jest/Playwright في المشروع الأصلي، كما لا يوجد script للاختبارات في `package.json` الأصلي. Scripts الأصلية تتضمن `dev`, `build`, `lint`, `remotion`, `render`, و`deploy`.

## أنظمة قابلة لإعادة الاستخدام مستقبلًا

1. Remotion كمحرك تركيب وعرض أساسي، بعد تمرير مواصفة بيانات مستقلة إليه.
2. أنماط واجهة Next.js وReact، مع إنشاء واجهة جديدة مستقلة بدل ربط حزم الأصل.
3. OpenAI/AI SDK كأحد موفري الذكاء الاصطناعي الممكنين لاحقًا، خلف واجهة موحدة وفحص اعتماداته.
4. مهارات Remotion كمرجع هندسي، لا كجزء تنفيذي من النسخة الجديدة.
5. التكامل مع Lambda كخيار مستقبلي بعد إنشاء RenderJob موحد وآمن.

## المخاطر والقيود

- تنفيذ شيفرة LLM بواسطة `new Function` خطر عزل رئيسي، ولا ينتقل إلى النسخة الجديدة.
- لا يُستنتج تفعيل أي مزود أو صلاحية من وجود اسم متغير بيئة في ملف مثال.
- الاعتماد على حزم الجذر أو مساراته سيكسر استقلال التثبيت؛ النسخة الجديدة لها `package.json`, lockfile, TypeScript config وNext config مستقلون.
- الأصل لا يملك اختبارات آلية ظاهرة. بناء الأصل لم يُشغّل؛ لذلك لا يوجد ادعاء عن نجاحه أو فشله.
- لا تُستخدم Pinterest scraping ولا خدمات Adobe أو TTS في Phase 1.

## خط أساس الحماية

قبل إنشاء النسخة الجديدة كان `git status --short --branch` نظيفًا على فرع Arena الثابت. يجب أن تظل كل التغييرات الخاصة بهذه المهمة محصورة في `fqmg-ohz-next/`. لا تعديل أو نقل أو حذف لملفات الأصل.
